# Qilma-API

Qilma API is a backend service for a word-guessing game.
It provides endpoints for gameplay, guesses, statistics, authentication, guests, password resets, and user management.

---

## Features

* User accounts and JWT-based authentication
* Game creation and guess submission
* Guest gameplay with statistics
* Password reset workflow via email
* Word validation using Hunspell
* Random word generation
* Strong password hashing with BCrypt
* Email delivery through MailKit
* PostgreSQL database with Entity Framework Core
* Interactive Swagger UI

---

## Endpoints Overview

### Tokens

```
POST /tokens
```

### Users

```
POST /users
GET /users/me
PUT /users/me
DELETE /users/me
GET /users/me/statistics
PUT /users/me/password
```

### Games

```
POST /games
POST /games/{gameId}/guess
```

### Guests

```
POST /guests
GET /guests/me/statistics
```

### Passwords

```
POST /passwords/reset/request
POST /passwords/reset/confirm
```

## Running the Project

1. Install .NET 10.
2. Create a `.env` file in the project root with the following variables:

```
DB_PASSWORD=your_db_password

JWT_KEY=your_jwt_key

EMAIL_SENDER_NAME=Your_name
EMAIL_ADDRESS=your_email_address
EMAIL_APP_PASSWORD=your_email_app_password
SMTP_HOST=your_smtp_host
SMPT_PORT=your_smtp_port

FRONTEND_URL=your_frontend_url

```

`Program.cs` automatically loads these values at startup using DotNetEnv.
These keep sensitive data out of your source code.

3. Navigate to the project folder containing `Program.cs`:

```bash
cd Qilma-API
dotnet run
```

4. The API will start with Swagger UI enabled. Visit http://localhost:port/swagger/index.html (replace port with the one shown in the console).
5. Ensure FRONTEND_URL in `.env` matches your frontend application.
6. **Database:**

   * If you use PostgreSQL locally, ensure the connection string in `appsettings.json` points to your local DB.
   * If your PostgreSQL database is empty, run migrations to create the tables:

     ```bash
     dotnet ef database update
     ```
   * If the tables are already created on the database, you can skip running migrations.

## Security Notes

* Never store passwords, JWT keys, email credentials, or any sensitive information in source code.
* Always use environment variables for sensitive values.
* Update CORS to allow only the correct frontend domain.
* Use HTTPS in production.
